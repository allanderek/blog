# Home Page Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the bare paginated post list on the home page with a landing page that introduces Allan, links his ten best posts with blurbs, shows the eight most recent, and links to a new `/archives/` page.

**Architecture:** Intro prose lives in `content/_index.md` as ordinary markdown so it can be edited without touching templates. A new `layouts/home.html` renders that content, then two generated sections: "Start here" (posts flagged `featured: true`, ordered by `featuredWeight`) and "Recent" (newest eight). PaperMod's built-in `archives` layout provides the full list. Styling goes in `assets/css/extended/home.css`, which PaperMod concatenates automatically.

**Tech Stack:** Hugo 0.146.7 (extended) locally, Hugo 0.139.0 in CI; PaperMod theme (git submodule, v8.0-15-ga020be2); Go HTML templates; plain CSS.

## Global Constraints

- **Spec:** `docs/superpowers/specs/2026-08-12-home-page-design.md`. Read it before starting.
- **Verify with production builds.** Run `hugo`, not `hugo server`. The dev server skips production-only templates and therefore proves less. Check Hugo's own exit status; never pipe Hugo through another command and read that command's status.
- **CSS must use PaperMod's existing custom properties** (`--border`, `--secondary`, `--content`, `--primary`) so both light and dark themes work without extra rules.
- **Do not modify anything under `themes/`.** It is a git submodule. Override by creating files at the same path under `layouts/`.
- **Do not touch** `.github/workflows/` (CI Hugo version) or the theme submodule pointer. Both are explicitly out of scope per the spec.
- **Availability line is a placeholder.** Write it as the literal text given in Task 3 and do not invent wording.
- **Featured blurb text is fixed.** Copy the strings in Task 5 verbatim from this plan; they were reviewed and approved.

- [ ] **Step 2: Write the verification harness**

Create `check-site.sh`:

```bash
#!/usr/bin/env bash
# Builds the site with a production build and asserts the results.
# Run: ./check-site.sh
set -uo pipefail

OUT=$(mktemp -d)
trap 'rm -rf "$OUT"' EXIT
fail=0

# check <description> <shell expression>
check() {
  if eval "$2" >/dev/null 2>&1; then
    printf '  ok    %s\n' "$1"
  else
    printf '  FAIL  %s\n' "$1"
    fail=1
  fi
}

echo "Building (production) into $OUT"
if hugo --destination "$OUT" >"$OUT/build.log" 2>&1; then
  printf '  ok    hugo build exits 0\n'
else
  printf '  FAIL  hugo build exits 0\n'
  grep '^ERROR' "$OUT/build.log" | head -5
  echo
  echo "Build failed; skipping remaining checks."
  exit 1
fi

check "no ERROR lines in build output" "! grep -q '^ERROR' $OUT/build.log"

exit $fail
```

Make it executable:

```bash
chmod +x check-site.sh
```

```go-html-template
{{- define "main" }}

{{- /* Intro prose lives in content/_index.md so it can be edited without
       touching this template. */}}
<article class="home-intro">
  {{ .Content }}
</article>

{{- /* Recent: newest posts. site.RegularPages is already newest-first. */}}

    {{- end }}
  </ul>
  <p class="home-all-posts">
    <a href="{{ "archives/" | relURL }}">All {{ len $posts }} posts &rarr;</a>
  </p>
</section>
{{- end }}

{{- end }}
```

The post count is computed from `$posts`, never hardcoded, so it stays correct as posts are added.

```go-html-template
{{- /* Start here: hand-picked posts, ordered by featuredWeight ascending.
       A post with no featuredWeight is read as 999 so it sorts after the

       is pre-sorted newest-first so that any equal weights fall back to date. */}}
{{- $featured := where site.RegularPages "Params.featured" true }}
{{- if $featured }}
{{- $ranked := slice }}
{{- range $featured.ByDate.Reverse }}

{{- end }}
<section class="home-section" id="start-here">
  <h2>Start here</h2>
  <ul class="home-featured">
    {{- range sort $ranked "weight" }}
    {{- $p := .page }}
    <li class="home-featured-item">
      <a href="{{ $p.RelPermalink }}">{{ $p.Title }}</a>
      {{- with $p.Params.featuredBlurb }}
      <p class="home-blurb">{{ . }}</p>
      {{- end }}
    </li>
    {{- end }}
  </ul>
</section>
{{- end }}
```

## Notes for the implementer

- **If a `check` line passes when you expect it to fail,** you have probably written the shell expression wrongly rather than discovered that the work is already done. `check` runs `eval` and only inspects the exit status, so a malformed expression can pass by accident. Verify by temporarily inverting the expression.
- **`grep -c` counts matching lines, not matches.** All the counted classes above are emitted one per line by the templates as written. If you reformat the templates so two items land on one line, the count assertions will silently under-count.
- **Do not add `draft: true` anywhere** to hide a post. The spec has no drafts in it.
- **Resist adjacent fixes.** Two real problems are deliberately left alone, and
  fixing them here would widen the diff beyond what was approved:
  - 68 posts tag `elm` and 6 tag `Elm`, producing two separate tag pages. The
    home page displays no tags, so it is not this work's problem.
  - `layouts/index.atom.xml` reads `.Site.Author`, which is the deprecated
    `[author]` config table, not `[params] author`. Adding `params.author` in
    Task 2 will therefore *not* change the feed's author element. That is
    expected, not a bug in your work.
